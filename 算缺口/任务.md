# 任务：用每日销量预测替代 7/30 天加权缺口模型

## 背景

当前项目是发货建议工具，核心逻辑在：

- `src/shipment_planner/engine.py`
- `src/shipment_planner/parsers.py`
- `src/shipment_planner/cli.py`
- `src/shipment_planner/reports.py`
- UI 在 `src/planner_ui/`

现在已经有 Temu 每日销量文件，字段包括：

- `平台SKC_ID`
- `平台SKU_ID`
- 多个日期销量列，例如 `03月20日销量`、`04月19日销量`

现有 `parse_temu_daily_sales()` 已能解析为：

```python
dict[tuple[str, str], tuple[int, ...]]

也就是：

(SKC, SKUID) -> 每日销量序列，按旧到新排序

## 目标

彻底抛弃当前 7/30 天加权预测模式。

以后缺口预测必须基于每日销量序列。

不要 fallback。
如果缺少 Temu 每日销量文件，或者某个需要计算的 SKU 找不到每日销量数据，程序应该直接报错，而不是回退到近 7 日 / 近 30 日销量。

## 新模型要求

每个 SKU 最终只输出一个建议量。

内部可以判断该 SKU 当前适合：

- 保守
- 正常
- 激进

但报表里只新增一个策略列，例如：

预测策略

显示 保守 / 正常 / 激进 之一。

建议发货量仍然只保留一个：

建议发货量

## 建议预测逻辑

替换当前：

近30日销量 * sold30_weight + 近7日销量 * sold7_weight

改为：

预测备货期销量 = 预测日均销量 * 备货逻辑天数
缺口 = ceil(max(0, 预测备货期销量 - 可用库存))
建议量 = min(订单需求量, 缺口)

可用库存保持现有口径：

平台仓内库存 + 平台待收货库存 + 发货中数量

## 策略判断建议

根据每日销量序列自动判断策略：

保守：
- 最近销量明显下滑
- 波动极大
- 出现疑似异常暴涨后回落
- 历史销量不稳定，容易误补

正常：
- 销量相对稳定
- 没有明显突增/突跌
- 波动在合理范围内

激进：
- 最近销量持续上升
- 近期销量水平明显高于历史稳健水平
- SKU 有热销标记

注意：SKU 可能无征兆暴涨或暴跌，所以不要让单日异常完全决定预测。需要做稳健处理。

## 第一版模型建议

可以实现一个可解释的稳健算法，不要上复杂机器学习。

建议：

1. 从每日销量序列中计算：
    - days_count
    - total_sales
    - mean_daily
    - median_daily
    - recent_7_avg，如果数据不足 7 天则用可用天数
    - recent_3_avg，如果数据不足 3 天则用可用天数
    - max_daily
    - volatility
2. 异常处理：
    - 单日销量远高于中位数时，不要完全按爆发日均值预测
    - 单日销量为 0 不一定代表需求为 0，尤其库存为 0 时要谨慎
3. 策略选择：
    - recent_3_avg > median_daily * 1.5 且最近几天不是单日孤立暴涨，可以判为 激进
    - recent_3_avg < median_daily * 0.6 或波动很大，可以判为 保守
    - 其他为 正常
4. 预测日均销量：
    - 保守：偏向 median_daily 或截尾均值
    - 正常：结合 median_daily 和 recent_7_avg
    - 激进：结合 recent_7_avg 和近期上升趋势，但设置上限，避免被一天爆单带偏

## 报错要求

不要 fallback。

以下情况应直接报错：

1. 没有提供 Temu 每日销量文件
2. Temu 每日销量文件缺少 平台SKC_ID 或 平台SKU_ID
3. Temu 每日销量文件没有任何 x月x日销量 列
4. 订单中需要计算的 (SKC, SKUID) 在每日销量数据中找不到
5. 某个 SKU 的每日销量序列为空
```
